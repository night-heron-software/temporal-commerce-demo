## Changes made this pass

### Checkout: `validating|shipping|payment|review` → `validating|collecting` (mono `919553b`)

Mono collapsed the three step-states into one prerequisite-accumulation `collecting` state on
2026-06-26; the WS3/WS4 port kept the old graph. Now aligned:

- `types.ts` — `CheckoutStateName = 'validating' | 'collecting'`; `CheckoutStep` stays the
  UI-facing union; `SubmitOrderSignal`/`CheckoutInput` gained optional `reviewedCartVersion`
  (mono's price-integrity guard: a stale reviewed version aborts submit with `CART_CHANGED`).
- `checkout-decider.ts` — facts renamed to mono vocabulary (`CartLoaded`, `ShippingSet`,
  `ShippingFailed`, `PaymentSet`, `OrderSubmitted`, `SubmitRejected`, `Cancelled`,
  `Recomputed`, …); `evolve` no longer writes the UI `step`.
- `states.ts` — single `collecting` state carrying all inputs + `onTimeout`/`onSignal`
  (recompute); `setPayment` is now order-independent (prerequisite enforcement lives in
  `submitOrder`); submit failure returns to `collecting` (previously → `payment`).
- `workflows.ts` — `deriveStep()` derives shipping → payment → review from prerequisites;
  `onContextUpdate` maps `collecting` through it. The wire `CheckoutState.step` is injected at
  every boundary (query handler, update formatters, final result), so the storefront contract
  is unchanged.
- Tests mirrored from mono's `states.test.ts` (prerequisite rejection, CART_CHANGED abort,
  submit freeze/thaw, recompute un-check, timeout cancel); diagrams + docs regenerated.

### Fulfillment: decider fact/command vocabulary → mono names

Behavior unchanged; renames only. Parent (`fulfillment-decider.ts`):
`FulfillmentCancelled → OrderCancelled`, `FulfillerOrderReported → ChildStatusApplied`,
command `childStatusReported → childStatus`. Child (`fulfiller-decider.ts`):
`AutoShipped/autoShipped → SimulatedShipped/simulatedShip`,
`AutoDelivered/autoDelivered → SimulatedDelivered/simulatedDeliver`,
fact `OrderCancelled → Cancelled`.

## Intentional differences kept (do not "fix" in future syncs)

- **No Stripe / no Twisp ledger** — mock payment provider; no PaymentIntent reuse
  (`updatePaymentIntent`) or `paymentIntentId` threading; no `recordPaymentAuthorization`,
  `persistDeliveryPromise`, ledger finalize actions (`recordCapture`/`recordRefund`/…), or the
  refund-saga child.
- **Reservations kept on payment failure** — mono releases reservations when `processPayment`
  fails; the demo keeps them for a submit retry (they expire via the inventory TTL). Locked in
  by a test in `states.test.ts`.
- **Best-effort submit freeze** — the demo wraps the cart freeze/thaw signals in try/catch (a
  missing parent must not block submit); mono signals unconditionally.
- **Single store** — `DEMO_STORE_ID` instead of `storeId` threading; plain numbers instead of
  `Money` value objects.
- **Cart** — no `mergeCarts` / `adoptCheckout` / `destroyCart` flows (mono has had them since
  before the extraction; demo never ported cart-merging).
- **Fulfiller child** — demo keeps the `submitted`/`OrderSubmitted` command/fact (mono handles
  submit inside the shell `prepare` with a strategy-descriptor router) and derives the simulated
  tracking number from the workflow id in the shell (mono derives it from the timestamp in
  `evolve`).
- **Identity** — demo keeps `updateShopperProfileWorkflow`/`updateShopperPasswordWorkflow`
  wrappers (mono uses standalone activities); no invite or API-token workflows.
- **Layout** — shared signal/query/update definitions live in `src/temporal/contracts/<domain>.ts`
  (mono: per-package `definitions.ts`); framework vendored at `src/temporal/framework/`
  (in sync with the `nightheron-state-machine` repo @ `708e0fe`, modulo Prettier width).
