# Mono sync — 2026-08-09

Forward-port of the **decider-native authoring surface** (ADR-0024, mono clarity plan
Phases 1–7) from `nightheron-mono` (`main` @ `a3cb60e`) and the framework repo
`nightheron-state-machine` (@ `01ec172`, through its PR #8). Previous sync:
[2026-07-25](mono-sync-2026-07-25.md) (mono `2c91659`, framework `7b1af7b`).

This is the demo's largest sync to date: the mono **deleted** the first-generation
authoring surface (`defineDomain` / `defineTransitions` / `definePureState` / `route`
and their types) after migrating all eight of its machine domains to `defineMachine` —
a framework-owned fold over a pure `{ decide, evolve }` decider, with per-state
`commands` (guard → prepare → enrich pipeline), event-keyed `route` tables, event-keyed
`effects`, `onTimeout` command synthesis, and typed rejection (`StateOutput.rejected`:
a refused input releases the caller with an error and neither transitions, records,
nor projects). The demo forward-ports the framework unconditionally (sync-guide §2.5)
and migrates all five of its machines: cart, checkout, oms, fulfillment, and the
fulfiller child.

## Intentional differences kept (do not "fix" in future syncs)

Carried forward from [2026-07-08](mono-sync-2026-07-08.md) and extended with how each
divergence now interacts with the decider-native surface:

- **No Stripe / no Twisp ledger** — mock payment provider; no PaymentIntent reuse or
  `paymentIntentId` threading; no `recordPaymentAuthorization`, `persistDeliveryPromise`,
  ledger finalize actions, or refund-saga child. *New surface:* mono's ledger/Stripe
  commands, events, and effects are simply absent from the demo's unions and effect
  maps; OMS keeps the demo's `computeRefundRecord` mock-refund path.
- **Reservations kept on payment failure** — mono releases reservations when
  `processPayment` fails; the demo keeps them for a submit retry (they expire via the
  inventory TTL). *New surface:* the payment-failure event's effect releases nothing;
  still locked in by a checkout `states.test.ts` case. Relatedly, the demo's
  `Cancelled` event carries the **pre-fold** reservation list so the cancel effect can
  release exactly what was held when the decision was taken.
- **Best-effort submit freeze** — the demo wraps the cart freeze/thaw signals in
  try/catch (a missing parent must not block submit); mono signals unconditionally.
  *New surface:* unchanged — the try/catch lives in the `submitOrder` prepare saga.
- **Single store** — `DEMO_STORE_ID` instead of `storeId` threading; plain numbers
  instead of `Money` value objects. Applies to every decider/state/contract file.
- **Cart** — no `mergeCarts` / `adoptCheckout` / `destroyCart` commands (mono has
  them; demo never ported cart-merging). *New surface additions:* reservations remain
  per-variant release-then-re-reserve (`reserveCartItem`/`releaseCartItem` — not
  mono's ADR-0022 absolute sku holds), so a failed re-reserve **compensates by
  restoring the old quantity before throwing** the rejection; `linkUser` carries
  `email` + `userId` (mono: `userId` only); the wire `CartUpdateResponse` stays
  `CartDetails | void` with `respond: (ctx) => ctx.cart` (mono wraps `{ cart }`); and
  the demo's `evolve` clears `checkoutWorkflowId` on `CartCompleted` (the child
  already closed — mono keeps the link).
- **Fulfiller child `submitted` command** — the demo keeps the explicit
  `submitted`/`OrderSubmitted` command/event pair; mono submits inside the shell
  prepare with a strategy-descriptor router the demo doesn't have (no plugin
  registry). *New surface:* `submitted` is a listed command on the rejection-retry
  path — a failed submit rejects (no transition) and the state's timer re-synthesizes
  the command, so the retry loop is now visible in the route/commands tables. The
  **simulated tracking number stays derived from the workflow id** in the handler's
  `prepare` (shell) and is enriched onto the command (mono derives from the timestamp
  in `evolve`). Timeouts stay **plain Durations** via `buildFulfillerOrderStates`
  (mono uses the new `(ctx) => Duration` strategy-descriptor resolver — the demo has
  no descriptors to resolve from). The parent `notifyParent` call stays in
  `onTerminal`, and the demo's `shipped → __terminal:failed` edge (delivery-failure
  simulation) is kept.
- **OMS** — no return-window / SLA timers (mono-only feature work); the demo's
  closed-set trigger-marker guard (demo PR #45 → mono `4480f79`) keeps its semantics
  on the new surface; the sku fallback in fulfillment hand-off is kept; delivered-state
  `updateStatus` narrowing lives in `guardDeliveredUpdateStatus` (pure guard, replaces
  the old mirrored prepare/decide checks).
- **Identity** — unchanged this sync (not a machine domain): demo keeps
  `updateShopperProfileWorkflow`/`updateShopperPasswordWorkflow` wrappers; no invite
  or API-token workflows.
- **Layout** — shared signal/query/update definitions live in
  `src/temporal/contracts/<domain>.ts` (mono: per-package `definitions.ts` +
  duplicated contracts); framework vendored at `src/temporal/framework/` (byte-status
  above). The command unions live in the contracts files and the domains' `types.ts`
  re-export them.

## Deliberately NOT ported

- Mono domains the demo never had: catalog, accounting, inventory
  transfer/replenishment/availability-sync/lead-time-calibration machines (the mono's
  Phase 2a/3 migrations of those domains have no demo counterpart; demo inventory
  remains the non-machine `inventoryServiceWorkflow` CQRS bridge).
- `@nightheron/state-machine` packaging changes (`./correlation` export subpath,
  build config) — the demo vendors sources, not the package.
- Mono docs rewrite (Phase 6) and ADR-0025 (Phase 5, "not adopted") — mono-repo docs;
  the demo has no equivalent doc surface to rewrite.
