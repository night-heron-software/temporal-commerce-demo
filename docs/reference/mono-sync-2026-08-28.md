### Why the cancellation fix matters here

The timeline used to stop at the last ordinary transition, with no terminal row and no gap marker,
so a cancelled workflow read as **still sitting in its last state**. Two independent causes, both
fixed: nothing _recorded_ an ending (the only `record()` call site is inside the main loop, and
external cancellation interrupts the loop rather than transitioning through it), and the flush
could not _survive_ (`shutdownRecorder()` awaits a coroutine created in the workflow's root scope,
already rejected by then; `CancellationScope.nonCancellable` only protects operations started
inside it).

### Added here, because it exists in neither repo

A test that cancellation **records** a terminal row and flushes it without the coroutine. The
framework's issue-#11 fix shipped untested; this repo's suite had no coverage either. Fail-proved
by removing the recording and confirming that test — and only that test — fails.

### Replay compatibility

Driver changes affect **parked** workflows: precedent `be1ea07`, where old-code children hit
`TMPRL1100` on replay. Posture here is unchanged — **new executions only**, and restart workers
after building (the stale-worker rule).

### The prettier dividend

`nightheron-state-machine` had no prettier config, so its source formatted to defaults (double
quotes, ~80 col) while both consumers enforce `singleQuote` / `printWidth: 100`. Every re-vendor
therefore needed a reformat pass, and the audit re-flagged those rows forever.

Fixed at the source in framework PR #15 before this group started. The measurable result: **14 of
21 shared framework files are now byte-identical** to the vendored copies, and every file copied
verbatim in this group passed `format:check` here **with no reformatting**. Future re-vendors of
untouched files are a plain `cp`.

### Open question for a later pass

Vendored framework files diverge in doc-comment **references**: the framework cites
`mono-backlog-068/069`, this repo cites its own `#20`/`#22`. Adapting them on each vendor is what
makes the files diverge permanently — the same trap the prettier fix just removed. New files in
this group were copied **verbatim**; existing files kept their adapted references, via surgical
edits rather than whole-file replacement. Worth deciding deliberately: converge on verbatim
vendoring, or keep adapting and teach `audit.mjs` to ignore comment-only deltas.

## ADR-0031 — the correlation id is its own key again (split from Group 2)

Sources: mono `a73e16f0` + `3ce5a7f5` (its R11), adapted to this repo's smaller surface — no
`user_carts` (cookie-only identity), no Stripe webhook, no ops sweeps, no Twisp.

### Ported

- **`requireCorrelationId()`** in `contracts/constants.ts` (pure, Temporal-free), and
  `buildWorkflowStartOptions` now **throws on a falsy-but-defined** correlationId instead of
  silently dropping the Search Attribute. `undefined` stays the documented singleton opt-out.
- **The cart workflow owns the journey key**: minted as its own UUID in `executeCartUpdate`
  (cookie-cached, scoped `<cartId>:<correlationId>` so it self-invalidates), returned on
  `CartDetails` from BOTH read paths — the query and every update response, each reading the
  workflow's own `CorrelationId` Search Attribute — and reconciled into the cache after every
  mutation (`USE_EXISTING` discards start options, so the minted value is never trusted).
- **Four entity-key fallbacks replaced with the throwing accessor**: cart→checkout child start,
  fulfillment→fulfiller-order child start, the reservation ES document, and `createOrder` (whose
  "keeps seed/api paths working" comment was stale — the checkout workflow is its only caller).
  `?? order.correlationId` / `?? doc.correlationId` reads stay: they carry the journey key the
  record itself holds, which is a journey-key source, not an entity-key fallback.
- **`framework/identity.ts`** takes the framework's ADR-0031 wording — now **byte-identical**
  with `nightheron-state-machine` (15 of 21 files converged).
- **ADR corpus**: 0031 copied with the Provenance/Divergence banner; 0022 marked superseded in
  part; 0019 restored with its 2026-07-30 entity-key-fallback amendment **withdrawn** (that
  amendment cited "exactly as temporal-commerce-demo does" — this repo was the fallback's origin,
  and it now removes it); README index updated.

### Tests

Three old-model pins updated, each verified to discriminate: the start-options assertion now
requires the CorrelationId to be a UUID **and differ from** the cartId (presence alone passes
under the welded model); the two cookie-retirement tests expect both identity pointers to retire
together; and the states test asserting the exact cartId fallback ADR-0031 removes is inverted to
assert the refusal (`rejected: true`, `/No CorrelationId available/`, no child started). New:
`requireCorrelationId` + empty-string-throw coverage in `constants.test.ts`, whose existing
independence tests passed unchanged — the model is being restored, not invented.

### Replay + posture

Clean break, new executions only: an in-flight journey started under the welded model would hit
the checkout-child-start throw on its next transition. Restart workers after build; a `dev:init`
wipe is the honest reset.
