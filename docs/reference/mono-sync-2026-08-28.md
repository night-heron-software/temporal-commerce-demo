### Why the cancellation fix matters here

The timeline used to stop at the last ordinary transition, with no terminal row and no gap marker,
so a cancelled workflow read as **still sitting in its last state**. Two independent causes, both
fixed: nothing *recorded* an ending (the only `record()` call site is inside the main loop, and
external cancellation interrupts the loop rather than transitioning through it), and the flush
could not *survive* (`shutdownRecorder()` awaits a coroutine created in the workflow's root scope,
already rejected by then; `CancellationScope.nonCancellable` only protects operations started
inside it).

### Reconciled — kept this repo's version, deliberately

Vendoring wholesale would have imported regressions. Each of these is a case where **the demo is
ahead of the framework**:

| Kept | Why |
| --- | --- |
| **`UNRESOLVED_TIMEOUT_FALLBACK` park-and-warn** in `driver.ts` | The framework replaced it with `stateConfig.timeout!`, justified by "the startup check guarantees a declaration exists". That is unsound: the startup check explicitly counts a `timeout` **function** as declared, and a function can resolve `undefined` on any given iteration. The assertion is wrong precisely where the fallback exists. Backported to the framework in Phase B |
| **`driver.test.ts` in full** | This repo's file has **24 tests to the framework's 18**. The framework's lacks the park-and-warn test, both continue-as-new trigger tests, and two startup-check tests, and would have deleted the `warnCalls` capture that makes the park-and-warn assertable |
| **The `continueAsNewThreshold` doc comment** in `types.ts` | The framework deleted it outright. It is correct as written — it already describes the threshold as secondary to the SDK suggestion — so only the *code* needed the fix, not the documentation |
| **`machine.ts`** (not ported) | Comment-only difference; this repo's cites its own backlog #18. Cosmetic |
| **`identity.ts`** (deferred, not skipped) | The framework's wording is correct **under ADR-0031**, which this repo has not adopted yet — it lands in Group 2. Taking the comment now would make it describe behaviour the code does not have. Deferred so comment and code land together |

### Added here, because it exists in neither repo

A test that cancellation **records** a terminal row and flushes it without the coroutine. The
framework's issue-#11 fix shipped untested; this repo's suite had no coverage either. Fail-proved
by removing the recording and confirming that test — and only that test — fails.

### Replay compatibility

Driver changes affect **parked** workflows: precedent `be1ea07`, where old-code children hit
`TMPRL1100` on replay. Posture here is unchanged — **new executions only**, and restart workers
after building (the stale-worker rule).

### The prettier dividend

`nightheron-state-machine` had no prettier config, so its source formatted to defaults (double
quotes, ~80 col) while both consumers enforce `singleQuote` / `printWidth: 100`. Every re-vendor
therefore needed a reformat pass, and the audit re-flagged those rows forever.

Fixed at the source in framework PR #15 before this group started. The measurable result: **14 of
21 shared framework files are now byte-identical** to the vendored copies, and every file copied
verbatim in this group passed `format:check` here **with no reformatting**. Future re-vendors of
untouched files are a plain `cp`.

### Open question for a later pass

Vendored framework files diverge in doc-comment **references**: the framework cites
`mono-backlog-068/069`, this repo cites its own `#20`/`#22`. Adapting them on each vendor is what
makes the files diverge permanently — the same trap the prettier fix just removed. New files in
this group were copied **verbatim**; existing files kept their adapted references, via surgical
edits rather than whole-file replacement. Worth deciding deliberately: converge on verbatim
vendoring, or keep adapting and teach `audit.mjs` to ignore comment-only deltas.
